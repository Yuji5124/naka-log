# なかログ

**ふたりのお金を、かんたん記録。**

夫婦2人で使う、とにかく入力がかんたんな家計簿です。
「家計簿」というより、**夫婦2人のお金の生活ログ**。

```
カテゴリを押す（🍚 食費）→ 数字を押す（850）→ 完了
```

これだけで記録されます。保存ボタンはありません。押した瞬間に自動で保存されます。

---

## できること（v0.2）

| 画面 | できること |
| --- | --- |
| 今日 | 大きなカテゴリボタン（15種類・よく使う順）から記録。夫婦2人の記録が1本のタイムラインに並ぶ |
| カレンダー | 1か月の各日の合計。日付をタップすると、その日の記録（夫・妻それぞれの小計つき） |
| 集計 | 今月合計・誰のため（夫／妻／家族）・カテゴリ別・使った人別 |
| 設定 | この端末を使う人、**夫婦で同期**、予算、テーマ、バックアップ／復元、CSV書き出し |

- 記録をタップすると、金額・カテゴリ・使った人・誰のため・メモ・日時の修正、削除ができます
- 削除してもしばらく「元に戻す」ボタンが出るので、押し間違えても安心です
- 同じカテゴリを最近入力していれば「いつもの 電車 ¥220」のようなボタンが出て、数字を打たずに記録できます
- ネットがつながらない場所でも起動・記録できます（ホーム画面に追加した場合）
- **v0.2 の新機能：夫婦で同期** … ふたりのスマホで同じ記録を見られます（→「[夫婦で同期する](#夫婦で同期するv02)」）

## はじめかた

### 1. GitHub へアップロード

1. GitHub で、このアプリ用のリポジトリ（例：`naka-log`）を開きます
   - まだなければ、右上の「＋」→「New repository」で作ります。**Public（公開）** を選んでください
2. 「**Add file**」→「**Upload files**」をクリック
3. 上の「ファイル一覧」のファイルを**全部まとめて**ドラッグ＆ドロップ
4. 下の「**Commit changes**」をクリック

> 💡 すでに同じ名前のファイルがある場合は、上書きされます。

### 2. GitHub Pages を ON にする

1. リポジトリの上のメニューから「**Settings**」を開く
2. 左のメニューの「**Pages**」をクリック
3. 「Build and deployment」の「Source」で「**Deploy from a branch**」を選ぶ
4. 「Branch」で「**main**」と「**/(root)**」を選んで「**Save**」
5. 1〜2分待つと、ページ上部に公開URLが表示されます

> 💡 無料プランでは、リポジトリが **Public（公開）** でないと GitHub Pages を使えません。
> 公開されるのはアプリのプログラムだけで、**記録したお金のデータはそれぞれのスマホの中にだけ保存されます**（ネットには送られません）。

### 3. URL へアクセス

公開URLはこのような形です：

```
https://ユーザー名.github.io/リポジトリ名/
```

例：`https://yuji5124.github.io/naka-log/`

初めて開くと「**この端末を使うのは？**」と聞かれるので、

- 夫のスマホなら「👨 夫」
- 妻のスマホなら「👩 妻」

を選びます。以降、その端末で記録すると「使った人」が自動でその人になります（記録のときにワンタップで変更もできます）。

### 4. iPhone のホーム画面へ追加

> ⚠️ **大事**：iPhoneでは、**Safariで開いたなかログ** と **ホーム画面から開いたなかログ** は、記録が**別々に保存**されます。
> 記録を始める前に、先にホーム画面へ追加して、そこから使い始めてください。

1. iPhone の **Safari** で公開URLを開く
2. 画面下の **共有ボタン**（□に↑のマーク）をタップ
   - 見当たらないときは「…」→「共有」
3. 下のほうにある「**ホーム画面に追加**」をタップ
4. 名前が「なかログ」になっていることを確認して「**追加**」
5. 以降は、ホーム画面の「なかログ」アイコンから開きます

**Android（Chrome）の場合**：右上の「︙」→「**ホーム画面に追加**」または「**アプリをインストール**」。

ふたりとも、それぞれのスマホで 3 → 4 を行ってください。

## 使い方

1. 下の大きなボタンからカテゴリを押す（🍚 食費、🚃 交通 など）
   - よく使うものほど上に並んでいます。ほかのカテゴリは、ボタンの欄を上にスクロールすると出てきます
2. 数字を押す（`+100` `+500` `+1,000` ボタンも使えます）
3. 「**完了**」を押す

それだけです。必要なときだけ、入力画面の下で次を変えられます。

- **使った人**：お金を払った人（👨 夫 / 👩 妻）
- **誰のため**：誰のための支出か（👨 夫 / 👩 妻 / 👪 家族）
  - 例：妻が子どもの物を買った → 使った人＝妻、誰のため＝家族
  - 最初の「誰のため」は、カテゴリごとに決まっています（あとでワンタップで変えられます）
    - 「家族」：食費・日用品・子ども・通信費・光熱費・固定費・税金・その他
    - 「使った人」：飲み物・交通・経費・打合わせ・娯楽・衣服・美容
- **メモ**：なくてもOK

**ちょっとしたコツ**

- 昨日の分を忘れていたら、今日画面の日付の「＜」で昨日にしてから記録します
- カレンダーで日付を選んで「＋ この日に記録する」でもOK
- ⌫ を長押しすると、金額を全部消せます
- 記録をタップ →「🔁 もう一度記録」で、同じ内容を今の時刻で記録できます

## 夫婦で同期する（v0.2）

ふたりのスマホで、同じ記録が見られるようになります。
奥さまが記録すると、数秒であなたのスマホのタイムラインにも出てきます。

準備は**最初に1回だけ**（10分くらい）。Googleの無料サービス「Firebase」を使います。
**A はパソコンでやるのがおすすめ**です（スマホのブラウザでもできます）。

### A. Firebase を準備する（はじめる人だけ・1回だけ）

1. [Firebase コンソール](https://console.firebase.google.com) を開き、Googleアカウントでログイン
2. **「プロジェクトを作成」** をクリック
   - 名前は `naka-log` など好きなものでOK →「続行」
   - Gemini や Google アナリティクスは **オフ** でOK →「プロジェクトを作成」
3. **匿名ログインを有効にする**
   - 左のメニュー「構築」→ **「Authentication」** →「始める」
   - 「ログイン方法（Sign-in method）」タブ → **「匿名」** → 有効にする →「保存」
4. **データベースを作る**
   - 左のメニュー「構築」→ **「Firestore Database」** →「データベースを作成」
   - ロケーションは **`asia-northeast1`（東京）** がおすすめ
   - **「本番環境モード」** を選んで「作成」
5. **ルールを貼り付ける**（大事）
   - Firestore Database の **「ルール」** タブを開く
   - 書かれている内容を **全部消して**、このリポジトリの [`firestore.rules`](firestore.rules) の中身を **全部** 貼り付け → **「公開」**
6. **設定をコピーする**
   - 左上の ⚙（歯車）→ **「プロジェクトの設定」** → 下のほうの「マイアプリ」→ ウェブのマーク **`</>`**
   - アプリのニックネームに `naka-log` と入れて「アプリを登録」（Firebase Hosting のチェックは不要）
   - 表示される `const firebaseConfig = { apiKey: ... };` の部分を **コピー**
   - パソコンで作業した場合は、LINE などで **あなたのスマホに送って** おきます

> 💰 **料金**：無料プラン（Spark）のままで使えます。クレジットカードの登録も不要です。
> 夫婦2人の家計簿なら、無料の範囲に十分おさまります。

### B. あなたのスマホでつなぐ

1. ホーム画面のなかログ →「設定」→ **「夫婦で同期」**
2. 枠の中に、コピーした `firebaseConfig` を **貼り付け**（前後に余計な文字があっても大丈夫です）
3. 「✓ Firebaseの設定を読み取りました」と出たら **「はじめる」**
4. 「☁️ 同期済み」になり、**招待コード** が表示されます

### C. 奥さまのスマホで参加する

1. あなたのスマホで **「LINEなどで送る」** を押して、奥さまに送る
2. 奥さまのスマホ：ホーム画面のなかログ →「設定」→ **「夫婦で同期」**
3. 届いたメッセージを長押しでコピー → 枠に **貼り付け**（メッセージ丸ごとでOK）→ **「参加する」**
4. ふたりの記録が、1本のタイムラインにまとまります 🎉

それぞれのスマホにすでにあった記録も、そのまま「ふたりの記録」に加わります。

### 同期について知っておくこと

- 記録の本体は、今までどおり **スマホの中** にあります。クラウドにはその写しを置いて共有しています
- **ネットがなくても記録できます**。つながったときに自動で送られます
- ホーム画面の右上に、同期の状態が出ます（押すと設定の「夫婦で同期」へ）

  | 表示 | 意味 |
  | --- | --- |
  | ☁️ 同期済み | ふたりの記録がそろっています |
  | 🔄 同期中 | 送っているところです |
  | ⏳ 未送信 3件 | ネットにつながったら送ります（記録はスマホに保存済み） |
  | 📴 オフライン | ネットにつながっていません |
  | ⚠️ 同期エラー | 設定に問題があります（押すと理由が出ます） |

- 同じ記録をふたりがほぼ同時に直したときは、**あとから直した方** が残ります
- 予算・呼び名・カテゴリ名も、ふたりで共有されます（「この端末を使う人」とテーマは端末ごと）
- 「データをすべて削除」は、同期中は **ふたりのスマホから** 消えます
- **機種変更したとき**：新しいスマホでなかログを開き、もう一方のスマホに出ている招待コードを貼り付けて「参加する」と、記録がすべて戻ります
- **やめたいとき**：設定 →「この端末の同期をやめる」。その端末の記録はそのまま残ります
- ⚠️ **招待コードを知っている人は、ふたりの記録を見られます。** 夫婦以外には送らないでください

### うまくいかないとき（同期）

| 表示 | こうしてください |
| --- | --- |
| 「匿名」ログインを有効にしてください | A-3 をやり直す（「匿名」が「有効」になっているか） |
| 「ルール」が設定されていないか… | A-5 をやり直す（最後に「公開」を押したか） |
| Firestore Database がまだ作られていない | A-4 をやり直す |
| 読み取れませんでした | `apiKey` から `appId` までが入るように、もう一度コピー |
| 共有が見つかりません | 招待コードが途中で切れていないか確認して、もう一度コピー |

## データについて（必ずお読みください）

- 記録は **そのスマホの中** に保存されます（「夫婦で同期」を使うと、その写しがクラウドで共有されます）
- 次のようなときは記録が消えることがあります
  - スマホの機種変更・故障・初期化
  - ホーム画面の「なかログ」アイコンを削除したとき
  - iPhoneの「設定 → Safari → 履歴とWebサイトデータを消去」をしたとき
  - （夫婦で同期していれば、招待コードを貼り付け直すとクラウドから戻せます）
- そのため、**月に1回くらい「設定 → JSONでバックアップ」** をしておいてください
  - iPhoneでは共有画面が出るので「ファイルに保存」を選ぶと、iCloud Drive などに保存できます
  - しばらくバックアップしていないと、今日画面にお知らせが出ます
- 復元は「設定 → JSONから復元」でバックアップファイルを選ぶだけです
  - **今ある記録は消えません**（同じ記録はより新しい方が残ります）
  - 機種変更のときも、古いスマホでバックアップ → 新しいスマホで復元、でOKです
- 「CSVで書き出す」で、Excel や Numbers で開ける表にできます
- 保存に失敗したときは、画面の上に赤いお知らせが出ます

## アプリを更新するとき

1. 新しいファイルを、はじめと同じ「Add file → Upload files」で上書きアップロード
2. 1〜2分待つ
3. スマホでなかログを開く（ネットにつながった状態で）

ネットにつながっていれば、自動で新しいファイルを読み込む仕組みになっています。
古い画面のままのときは、なかログを**完全に閉じて**（アプリ切り替え画面で上にスワイプ）からもう一度開いてください。

> ⚠️ 表示がおかしくても、「Safariの履歴とWebサイトデータを消去」は**記録も消えてしまう**ので、やる前に必ずバックアップしてください。

## 開発メモ

### データの形

```js
{
  id: "uuid",
  amount: 850,                 // 円（整数）
  category: "food",            // food / drink / daily / transport / kids / expense / meeting / fun /
                               // clothes / beauty / telecom / utilities / fixed / tax / other
  payer: "self",               // 使った人：self / wife
  for: "family",               // 誰のため：self / wife / family
  datetime: "2026-10-03T03:15:00.000Z", // いつの支出か（ISO 8601）
  memo: "",
  createdAt: "...",
  updatedAt: "...",            // 同じ記録が両方で変わったら、新しい方を残す
  deletedAt: null              // 削除は「削除済みの印」を付ける（論理削除）。同期で削除を伝えるため
}
```

「入力した人（payer）」と「誰のためのお金か（for）」を分けて持っています。
カテゴリ名・呼び名は表示用の設定なので、変えても過去の記録は壊れません。

### 保存と同期のしくみ

```
画面（今日・カレンダー・集計・設定）
   ↓ 使うのはこれだけ
Repository（add / update / remove / restore / merge / applyRemote）
   ↓
StorageAdapter … 記録の本体（端末内）
   ├ IndexedDBAdapter    … 通常はこれ
   └ LocalStorageAdapter … IndexedDBが使えないときの予備
        ↑↓ 未送信の変更（outbox）を送る ／ 届いた変更を取り込む
Sync（Firebase / Cloud Firestore）… 夫婦で同期を使うときだけ動く
```

- **端末内が本体**：画面はいつも端末内のデータだけを見ます。ネットや Firebase に問題があっても記録は続けられます
- **outbox**：同期中は、記録の保存と同じ IndexedDB トランザクションで「未送信」の印を書きます。送れたら消します
- **送信**：未送信分を30件ずつ、クラウドの updatedAt と比べて新しいものだけ書き込みます
- **受信**：`serverUpdatedAt`（Firestore のサーバー時刻）が前回受け取った位置以降の記録だけをリアルタイムで受け取ります。記録が増えても読み取り回数が増えにくい作りです
- **行き違いの修復**：受け取った記録より端末の方が新しければ、端末の方を送り直します。最終的に、ふたりとも一番新しい内容にそろいます
- **Firebase のプログラム** は同期を使うときだけ `https://www.gstatic.com/firebasejs/12.19.0/` から読み込み、service worker が保存するので圏外でも起動できます

Firestore の構造：

```
households/{共有ID}                 … settings（予算・呼び名）, devices（つながっている端末）
households/{共有ID}/transactions/{id} … 記録（上の形 ＋ serverUpdatedAt）
```

`firestore.rules` で、ログイン（匿名）していること・共有IDを知っていること・記録の形が正しいことを確かめています。
共有IDの一覧は取得できないようにしてあります。

### オフライン対応（service-worker.js）

- 方針は「**ネット優先 → だめならキャッシュ**」
- GitHub にファイルを上書きするだけで更新が届くので、バージョン番号を書き換える必要はありません
- パスはすべて相対パスなので、`https://ユーザー名.github.io/リポジトリ名/` の下でもそのまま動きます
- Firebase のプログラム（URLにバージョン入り）は、一度読み込んだら保存したものを使います
